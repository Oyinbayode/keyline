## Problem

An autocomplete is an input with a list under it, and it is one of the easiest controls to make unusable without anyone sighted noticing:

- **A styled `<div>` list with no roles.** Screen readers hear "edit text" and nothing else. The suggestions appear and change as the user types, and they never learn the list exists.
- **DOM focus moved into the list.** Arrowing down moves real focus to the first suggestion, so the next key the user types goes nowhere: typing stops working until they find their way back to the input.
- **Options not announced as they are arrowed through.** Focus stays in the input but nothing tells assistive technology which option is highlighted, so the arrow keys appear to do nothing.
- **No result count.** A blind user cannot tell that filtering happened, how many matches there are, or that there are none.
- **The first option auto-selected.** The list highlights its first match on every keystroke, so <kbd>Enter</kbd> submits something the user never chose, and a fast typist pressing <kbd>Enter</kbd> to submit the form gets the wrong value.
- **<kbd>Home</kbd> and <kbd>End</kbd> hijacked.** They jump to the first and last suggestion instead of moving the caret, so editing the typed text gets harder.
- **A list that closes on the press meant to select.** The input's `blur` runs on `mousedown`, the list closes, and the `click` lands on whatever is underneath it.
- **IME input broken.** Japanese, Chinese and Korean users confirm a composition with <kbd>Enter</kbd> and pick candidates with the arrows; key handlers that ignore composition choose an option or move the highlight halfway through a word.
- **Relying on `<datalist>`.** It needs no script, but its list cannot be styled, filtering rules differ between browsers, it does not exist the same way on every mobile browser, and screen reader support for its suggestions is inconsistent.

## Solution

`Combobox.Input` is a real `<input role="combobox">` named by a real `<label>`, and `Combobox.Content` is a `role="listbox"` shown as a native popover next to it.

- **Roles and relationships from the APG.** The input has `aria-autocomplete="list"`, `aria-expanded` and `aria-controls` pointing at the listbox. Options are `role="option"`, the chosen one has `aria-selected="true"`, and disabled ones `aria-disabled="true"`. Groups are `role="group"` named by their `Combobox.GroupLabel`.
- **Focus never leaves the input.** The active option is virtual: the input's `aria-activedescendant` points at it, so screen readers read it while the caret stays put and typing keeps working. The active option is scrolled into view.
- **A ring where the keyboard is.** The active option is a full-width slate-4 fill whether the pointer or the arrow keys put it there. The fill alone is faint against the list (about 1.2:1 in dark mode), so an option reached with the arrow keys also gets a 2px blue-9 keyline ring inset on all four sides, 5:1 or more against the list and the fill in both themes. A hovered option keeps the fill alone.
- **Nothing chosen for the user.** Typing opens and filters the list, but no option is highlighted until the user moves to one, so <kbd>Enter</kbd> with no active option chooses nothing. <kbd>Enter</kbd> on an active option fills the input with its text and closes the list.
- **A result count, said once.** A polite, visually hidden live region says "3 results" or "No results" half a second after typing settles. It is emptied on every keystroke and filled once, so it is not read for each letter, and a count still pending when an option is chosen is dropped. Pass `resultsMessage` to translate it, with your language's plural rules.
- **Editing keys stay editing keys.** <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>←</kbd> and <kbd>→</kbd> move the caret, as the APG specifies for editable comboboxes, and clear the active option, since visual focus is back in the text.
- **Pressing an option keeps focus.** The list and the button call `preventDefault()` on `pointerdown`, so the input is not blurred before the click lands, and the list stays open until the click chooses.
- **IME-safe.** No key is acted on while `isComposing` is true, so composing text with an input method works as it does in a plain input.
- **Leaving tidies up.** On blur the list closes. Text that names an option exactly (ignoring case and accents) chooses it; empty text clears the choice; anything else goes back to the chosen option's text, or to empty.
- **Filtering that forgives accents.** The default filter matches anywhere in the option's text, ignoring case and diacritics, so "cafe" finds "Café" and "cote" finds "Côte d’Ivoire". The matching characters get the print motif's keyline, a 2px underline in blue-9, on a real `<mark>`. Pass `filter` to match differently, or `filter={false}` when the options come already filtered from a server.
- **In the top layer, beside the input.** The list is a manual native popover, because focus must stay in the input, anchored with CSS anchor positioning: under the input, at least as wide as it, lined up with its inline start edge (the right under `dir="rtl"`), and flipped above when there is no room. It works inside a Keyline Dialog, where <kbd>Esc</kbd> closes the list, then clears the text, and only then closes the dialog.
- **A value set from outside shows its text.** When a parent changes `value` (a reset button, saved data loaded later), the input shows the new option's text, or nothing when the value is cleared, and the list is not filtered by the old text. If that option has not rendered yet, the input updates when it does.
- **Forms.** With `name`, a hidden input submits the chosen option's value, not the typed text.

## Props

`Combobox.Root` renders a `<div>` around the parts, the live region and the hidden form input. `Combobox.Label` renders a `<label>`, `Combobox.Input` an `<input>`, `Combobox.Trigger` a `<button>`, `Combobox.Content` a `<div role="listbox" popover="manual">`, and options, groups, group labels and the empty message render `<div>`s. Each part passes other props (`className`, `style`, `aria-*`, `data-*`, event handlers, `ref`) to its element. An `onClick` on an option that calls `event.preventDefault()` cancels the choice.

Styling hooks: `data-active="keyboard" | "pointer"` on the active option (only `"keyboard"` is ringed), `aria-selected` and `aria-disabled` on options, `:popover-open` on the open list, and `.kl-combobox-match` on the `<mark>`.

## Keyboard

| Key                                                           | Action                                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Typing                                                        | Opens the list and filters it. No option becomes active.                                    |
| <kbd>↓</kbd>                                                  | Opens the list on the first option, or moves to the next one, wrapping.                     |
| <kbd>↑</kbd>                                                  | Opens the list on the last option, or moves to the previous one, wrapping.                  |
| <kbd>Alt</kbd> + <kbd>↓</kbd>                                 | Opens the list without moving.                                                              |
| <kbd>Alt</kbd> + <kbd>↑</kbd>                                 | Closes the list.                                                                            |
| <kbd>Enter</kbd>                                              | Chooses the active option, fills the input and closes. With no active option, does nothing. |
| <kbd>Esc</kbd>                                                | Closes the list; on a closed list, clears the input. Otherwise left for a dialog.           |
| <kbd>Home</kbd> / <kbd>End</kbd>, <kbd>←</kbd> / <kbd>→</kbd> | Move the caret in the input.                                                                |
| <kbd>Tab</kbd>                                                | Closes the list without choosing, and moves on.                                             |

The button beside the input is skipped by <kbd>Tab</kbd> (`tabIndex={-1}`), as in the APG examples: everything it does is on the keyboard already.

### Manual checklist (Orca + Firefox, TalkBack + Chrome)

Run against the [Keyboard test fixture](?path=/story/components-combobox--keyboard-fixture) story and record results in `docs/manual-testing.md`.

1. Tab from "Before" into "Country". Expect "Country", combobox (or "edit, has autocomplete"), collapsed.
2. Type "cura" and wait. Expect "1 result" once, not a count per letter.
3. Press <kbd>↓</kbd>. Expect "Curaçao" to be read, with the caret still in the input.
4. Press <kbd>Enter</kbd>. Expect the input to read "Curaçao" and the list to close.
5. Clear the input, type "egy", press <kbd>↓</kbd>. Expect "Egypt", unavailable or dimmed; <kbd>Enter</kbd> does nothing.
6. Type "zz" and wait. Expect "No results".
7. Press <kbd>Esc</kbd> twice. Expect the list to close, then the text to clear.
8. TalkBack: type in the input, then swipe to the suggestions and double-tap one. Expect it to fill the input.
9. Visual: the active fill, the underline under the match, the tick on the chosen option and the disabled option are clear in both light and dark themes.

## Known limitations

- **Single selection only.** No multiple selection or tags yet.
- **No inline autocomplete.** The typed text is never completed in place (`aria-autocomplete="both"`); suggestions are only in the list.
- **No creating new options.** Text that matches no option is undone on blur; the combobox cannot add it.
- **No virtualised lists.** Every option is rendered; for thousands of options, filter on a server with `filter={false}` and render only the results.
- **The input is the anchor.** The list is at least as wide as the input, not the input and button together.
- **An empty list is not a listbox.** With no options to show, the list drops `role="listbox"` and shows `Combobox.Empty`; the live region says "No results".
- **Real Windows High Contrast and real IMEs have not been checked by hand,** only emulated.
